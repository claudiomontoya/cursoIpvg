Lo que hay que hacer

El proyecto

Tres pasos. Eso es todo.

Construye un chat web que responda preguntas utilizando un documento real de tu empresa o institución.

X
Consigue un documento
Un PDF, .txt o .md con información real de tu empresa o institución. Mínimo 3 páginas de contenido útil.
Ejemplos Manual del empleado · Reglamento interno · Catálogo de productos · Procedimiento técnico
Y
Construye un chat que lo lea
Página web con caja de texto. El backend en Python utiliza OpenAI Agents SDK y recupera fragmentos del documento (RAG) para responder.
Reutiliza La estructura ya está disponible en webapp_mcp_sdk/app.py
Z
Agrega una tool
Una función Python que el agente pueda invocar cuando necesite algo dinámico: un cálculo, una consulta, una fecha.
Ejemplos calcular_vacaciones(rut) · buscar_precio(item) · consultar_stock(id)
Ejemplo concreto

Un encargado de Recursos Humanos en una empresa de 80 personas. Su documento es el reglamento interno (PDF) y su tool es dias_vacaciones_disponibles(rut). El chat responde "¿cuántos días tengo?" combinando el reglamento (cómo se calculan) con la tool (cuántos quedan).

System prompt

Las instrucciones del agente

Adapta este prompt a tu caso

Completa los espacios marcados en amarillo. Estas instrucciones definen el comportamiento del bot y constituyen la mitad del proyecto.

# SYSTEM PROMPT

Eres un asistente de NOMBRE DE LA EMPRESA, especializado en
responder consultas sobre TEMA DEL DOCUMENTO.

Tu público corresponde a QUIÉNES TE PREGUNTAN (ej: empleados,
clientes, postulantes, técnicos de soporte).

Reglas de respuesta:
1. Si la pregunta es sobre TEMA, utiliza la tool
   buscar_documento para consultar la información oficial.
2. Para datos personales o cálculos dinámicos, utiliza la tool
   NOMBRE_DE_TU_TOOL.
3. Cita siempre la fuente cuando respondas con datos del documento.
4. Si no encuentras la respuesta, indica: "FRASE PARA
   CUANDO NO SEPAS". No inventes información.
5. Responde en español, con tono FORMAL / CERCANO / TÉCNICO.
Por qué funciona: entrega al modelo (1) un rol claro, (2) la condición para usar cada tool, (3) qué hacer cuando no sabe (evita alucinaciones) y (4) un tono consistente. Si el bot inventa información o no utiliza las tools, la solución casi siempre se encuentra en mejorar este prompt.

Opcional

Para quienes deseen profundizar

Si quieres ir más allá

Las siguientes extensiones son opcionales. Un proyecto bien hecho con X + Y + Z ya se considera completo.

Servidor MCP separado
Expone las tools desde un proceso aparte mediante MCP (como en webapp_mcp_sdk).
Más de un documento
Indexa dos o más fuentes y permite que el bot decida en cuál buscar.
Varias tools encadenadas
Diseña 2 o más tools y haz que el agente las combine en una misma respuesta.
Historial multi-turno
Que el bot recuerde lo conversado previamente en la misma sesión.
Tool con API real
Una tool que consulte un servicio externo real (clima, mapa, tipo de cambio).
Guardar conversaciones
Persistir preguntas y respuestas en un archivo o base de datos.
Publicar en línea
Desplegar el chat en un servicio (Render, Railway) con un enlace funcional.
Logs y métricas
Registrar qué tools se usan más, cuáles fallan y la latencia promedio.
Recuerda: realizar X + Y + Z correctamente puede obtener nota máxima. Las extensiones no son requisito ni suman puntos extra de forma automática: son una invitación a profundizar si el tema te interesa.
